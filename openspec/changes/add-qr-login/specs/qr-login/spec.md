## ADDED Requirements

### 需求:显示二维码登录入口
系统必须提供基于 `https://ncmapi.iamxyj.com/` 的二维码登录入口，并在未登录状态下向用户展示当前可扫码的二维码及其状态。

#### 场景:成功加载二维码
- **当** 用户进入未登录界面并触发二维码初始化
- **那么** 系统生成新的二维码登录会话并展示可供网易云音乐 App 扫码的二维码
- **那么** 系统展示“待扫码”或等效的初始状态文案

#### 场景:二维码初始化失败
- **当** 系统请求二维码登录会话或二维码数据失败
- **那么** 系统必须展示明确的错误状态
- **那么** 系统必须提供重新获取二维码的入口

### 需求:跟踪扫码登录状态
系统必须轮询二维码登录状态，并准确反映待扫码、已扫码待确认、登录成功和二维码过期四类关键状态。

#### 场景:用户已扫码但未确认
- **当** 轮询结果表明二维码已被扫码但尚未在移动端确认
- **那么** 系统必须将界面状态更新为“待确认”或等效文案
- **那么** 系统必须继续当前轮询直到状态终结

#### 场景:用户确认登录成功
- **当** 轮询结果表明二维码登录成功并返回有效会话信息
- **那么** 系统必须停止当前轮询
- **那么** 系统必须保存登录态并进入已登录状态

#### 场景:二维码已过期
- **当** 轮询结果表明二维码已过期
- **那么** 系统必须停止当前轮询
- **那么** 系统必须将界面状态更新为“二维码已过期”
- **那么** 系统必须提供刷新二维码的入口

### 需求:恢复并验证本地登录态
系统必须在应用启动时尝试恢复本地保存的单账号登录态，并通过查询当前用户基础信息验证该登录态是否仍然有效。

#### 场景:本地登录态有效
- **当** 应用启动时读取到本地保存的登录态且当前用户信息请求成功
- **那么** 系统必须直接进入已登录状态
- **那么** 系统必须展示当前用户的基础信息

#### 场景:本地登录态失效
- **当** 应用启动时读取到本地保存的登录态但当前用户信息请求失败或返回未登录
- **那么** 系统必须清理失效的本地登录态
- **那么** 系统必须回到未登录状态并重新提供二维码登录入口

### 需求:支持退出登录
系统必须允许已登录用户主动退出登录，并在退出后清理本地会话数据。

#### 场景:退出登录成功
- **当** 已登录用户执行退出登录操作且退出接口调用成功
- **那么** 系统必须清理本地保存的登录态与用户信息
- **那么** 系统必须回到未登录状态并展示新的登录入口

#### 场景:退出登录接口失败
- **当** 已登录用户执行退出登录操作但接口调用失败
- **那么** 系统必须向用户提示退出失败
- **那么** 系统禁止错误地将界面切换为未登录状态
